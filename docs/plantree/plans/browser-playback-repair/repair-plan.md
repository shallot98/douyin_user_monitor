原始审计使用少量文件头与 MP4 索引的 HTTP Range 请求，数据只进入内存，不保存视频。按作品 ID、文件下标和记录指纹去重，保存每条证据时间；后台新增作品不改变固定快照。后续已获“执行修复”授权，历史媒体处理仅在独立节点 boh 执行，实际结果见[执行证据](evidence/execution.md)。

## 按类型处理

| 问题 | 如何确认 | 修复路径 |
| --- | --- | --- |
| H.265/HEVC 播放文件 | MP4 `stsd` 记录 `hvc1/hev1`，目标浏览器不支持 HEVC | 复用已有 H.264 兼容副本，或在云端准备独立播放文件 |
| 当前地址读不到文件 | 当前网页接口读取失败，核对两盘及明确历史目录 | 找到同一作品的现存对象后修正映射；找到备份时以云端方式恢复；不能据一次路径失败断言原片已丢失 |
| 索引异常、空文件或仅音轨 | 复核实际对象大小、文件头、轨道与 Range 行为 | 从可验证的完整副本恢复，必要时在独立节点重新获取合法可用源；不要直接给异常文件改后缀 |
| 加密封装 | `encv/enca` 及相关保护描述，区别于普通 HEVC | 使用服务方提供的授权兼容播放源或现存未加密副本；没有可解码源时，普通转码不能解决 |
| H.264 但启动慢 | 实际首帧计时、索引在尾部、码率过高、反复建立连接 | 对播放副本前置索引、控制码率，并复用上游连接；不修改原片 |
| 封面缺失 | 记录无封面引用或图片对象读取失败 | 使用云端已有封面，或由独立节点提取小封面后直接保存 D2；单独记录展示问题 |

H.264 编码识别不等于每条作品已经通过完整浏览器验收。HEVC 的不兼容结论适用于不支持该编码的目标浏览器；支持 HEVC 的设备可能正常播放。

## 先恢复现存文件

利用作品记录中的原目录、清理后路径、明确的昵称历史及已有迁移记录核对云端对象。已实时确认“八月”“艾米粒儿”“给我一口甜”的三个报错样本在 D2、夸克的 `sec_<sec_user_id>` 历史目录中都存在，大小与下载记录相同；昵称路径的六次查询均失败，历史路径的六次查询均成功。

迁移脚本允许网盘拒收的普通中文目录改为 `sec_`，旧读取规则只在昵称清理后为空时生成这个目录，导致写入与读取规则不一致。修复复用已确认的历史精确路径，覆盖目录和文件名差异，仍由 D2 优先读取。866 条视频映射已全部安装，另修复 17 条封面映射；旧问题依据见[历史路径证据](evidence/historical-paths.md)，当前结果见[执行证据](evidence/execution.md)。

早期路径复核定位到 742 个对象，剩余 124 个已在执行阶段补齐依据并定位。其中早期 36 个对象的文件名也有差异，不能只改目录；有意义的原始空格不能一律清理后再查询。早期清单的 728 条大小对照与 14 条缺少旧大小参照的限制保留在[路径复核清单](evidence/path-recovery-inventory.md)，最终 866 条均通过网站与实际 D2 对象的大小、Range 和索引检查。

带作品 ID 的文件可以据 ID 精确定位。旧文件名没有作品 ID 时，结合发布时间、名称、大小以及服务商提供的内容标识确认；多候选不能自动选第一个。先输出只读匹配清单，再更新读取规则或文件引用。该步骤不需要下载媒体到本机。

找到原片后仍须检查编码。恢复地址只解决“读不到文件”，不能同时证明目标浏览器能够解码。

## 兼容播放文件标准

原片保持原路径及内容。默认播放文件采用 MP4、H.264、8-bit `yuv420p`、AAC 音轨，MP4 索引放在文件开头（faststart）。已有符合标准且足够轻量的文件直接复用，避免重复编码。

需要编码时，沿用项目当前播放参数作为起点：约 540p、30 fps、视频码率上限 1.2 Mbps、AAC 96 kbps、关键帧间隔 2 秒；保留比例，不放大低分辨率源。实际清晰度和启动速度由样本验收决定，不能仅凭参数宣称更快。

原始审计的 HEVC 条目中有 805 条已被旧记录标为播放版，因此不能凭 `fast_play` 名称或分辨率决定兼容性。另有 421 条 H.264 候选的索引在媒体数据之后；只有编码、尺寸、码率也合适时才仅重封装。实际普通队列为转码 10,533 条、仅重封装 51 条、仅补封面 1,816 条；另有 10 条恢复原片后再生成播放版。这些速度优化候选不全部计为已确认的不能播放。

派生文件使用与原片不同且可追溯的目标名/路径，保存源作品 ID、源对象标识、编码、尺寸、时长、码率、索引位置及验证时间。封面作为独立小图片，不依赖浏览器先读取视频才能显示。

## 云端执行路径

| 路径 | 当前依据 | 采用条件 |
| --- | --- | --- |
| 复用已存在的兼容云端文件 | 现有两盘文件和播放器可读取实际索引 | 编码、完整时长、访问和浏览器验收均通过 |
| D2 原生兼容播放流 | SDK 有 `video_codecs/audio_codecs`，协议有预览概念 | 字段语义、账号能力和真实返回编码得到验证；目前不能承诺可用 |
| 夸克兼容 MP4 → D2 云端导入 | 夸克响应含编码/时长/完成状态；D2 SDK 有离线 `parse/add/list` | 取到完整 H.264/AAC MP4，并验证 D2 能接受直链、鉴权、有效期和目标目录 |
| 独立计算节点 → D2 | boh 已完成 D2 试点及恢复原片交付，普通批量正在执行 | 当前采用；后台检查实际额度后上传，产物须完整验收 |

已检查网盘已有能力：D2 未给出兼容文件，夸克现有 Cookie 转码接口返回 `plf_invalid`。当前明确采用 boh 读取云盘原片、生成 H.264/faststart 播放文件与封面，再直接调用 D2 上传接口。普通 faststart MP4 在该节点生成完整文件后上传；项目本机不承担媒体临时存储。

2026-09-13 普通上传曾返回 HTTP 429、当日余额为 0；2026-09-14 额度恢复后已修复上传协议和证书问题，普通上传持续成功。HTTPS 离线源的早期 HEAD 200、parse 200/空对象、add 400/code 3 记录保留，未取得任务 ID；临时 origin 与 tunnel 已停止。该证据只说明本次导入失败，不能推断全部 HTTPS 导入均不支持。

项目本机只处理清单、任务状态和媒体元数据。独立节点从云盘直接读取、向 D2 直接上传，不能通过本机的视频代理拉取整片，也不能将产物交给本机 OpenList 上传。上游代码已确认：未知长度上传和异步上传可能全量缓存到本机磁盘。

现有 `/kuake` 挂载继续承担原片读取和复制。若使用夸克转码能力，须隔离为独立播放接口或挂载，按真实编码、完成状态及完整时长选择结果；不能全局打开转码地址。返回 HLS 清单时，不得把清单保存成 `.mp4` 当作修复完成。

官方接口、源码与历史限制见[云端能力研究](evidence/cloud-capabilities.md)。早期记录见[执行证据](evidence/execution.md)，当前试点与批量结果以[上传恢复验收](evidence/upload-recovery.md)为准；D2 试点已完成真实网页验收，整个队列仍未完成。

## 发布与并发

每条作品按“确认源对象 → 准备独立派生文件 → 上传 D2 → 完整解码复核 → 更新引用 → 网站 Range 检查”执行。恢复原片的任务额外先验收原始字节 SHA-256。云端任务已接收、上传接口返回成功、文件存在，都不能单独作为播放已修复的依据。

更新前核对作品记录是否仍对应统计时的源对象，并刷新 OpenList 中对应父目录和用户目录的缓存，避免直接写入 D2 后网站继续读旧目录列表。随后使用 `MonitorStorage.update_state` 在锁内按作品合并，保留原片引用、下载历史和其他作品信息；不整体覆盖旧 JSON 快照。

锁内更新必须重新读取磁盘状态，不能仅因缓存 mtime 相同复用旧快照。回执同步只传元数据，每 60 秒运行；网站请求须返回 HTTP 206 和精确总大小，才能记为 `published` 并推进检查点。若网站检查失败，已验证的 D2 引用可能已写入状态，但检查点不推进，下一次幂等重试并明确报告失败。

播放记录保存真实检测结果，页面只把已经验证的兼容文件标为可用播放版。遇到不可解码、文件缺失或准备失败，显示明确状态；不能靠空白播放器、音轨开始播放或静默选择不兼容文件隐藏失败。

## 验收和回退

- D2 文件实际索引确认 H.264/AAC、8-bit 像素格式、正确尺寸、完整时长和前置索引。
- 从网站接口检查 Range，再由目标浏览器确认真实视频帧、声音、拖动和重新打开；不能只检查 `playing` 事件。
- 首帧性能在相同网络、设备和冷/热缓存条件下比较，覆盖长短视频及不同账号；记录中位数和较慢样本，不预先保证全网速度。
- 核对原片对象标识、大小以及服务商可提供的内容标识未变，确认原片读取未被替换成转码地址。
- 核对本次修复任务没有向项目本机下载目录、上传缓存或临时目录写入历史视频；后台正常增量监控单独记录来源。
- 阶段程序在试点通过远端完整解码后继续原片恢复、普通批量；网站同步独立执行。D2 试点已通过真实浏览器验收，性能限制仍保留。保存修改前引用，必要时按当前记录逐条恢复，不能用旧全量状态覆盖增量作品。

## 剩余限制

1. D2 额度由多个上传任务共享，余额不足时以每 600 秒的接口结果为准，不猜重置时区或完成日期。
2. D2 试点能显示真实画面、解码音频、完整结束、拖动与重开；无头浏览器有掉帧记录，多设备流畅度没验证，也不能据单条试点宣布整个用户已修好。
3. 4 条特殊记录仍受加密、当前访问权限或内容本身不是视频的限制，逐条状态保留。
4. 普通队列仍需完成真实云端交付；已从当前状态消失的小暖暖 14 条记录不会重建。

原片保留、D2 为主要播放源、历史媒体不下载到项目本机的约束继续有效。
