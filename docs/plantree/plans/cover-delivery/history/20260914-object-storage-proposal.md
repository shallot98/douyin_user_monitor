## 覆盖范围

覆盖所有现有和新增用户的图文、视频封面。09:29 的元数据快照为 603 个用户、591 个已有作品的用户、22,296 条去重作品：9,428 条图文、12,868 条视频。独立封面引用只有 2,365 条；其余 8,481 条图文、11,450 条视频没有该引用。图文仍可能用第一张原图展示，不能把这些数字都算成封面加载失败。

依据：[全量范围与容量](../../../../../runtime/cover-delivery-plan-20260914/inventory.json)、[iamsoyi 实测](../../../../../runtime/iamsoyi-cover-diagnosis-20260914/report.md)。全量只统计了引用，未逐个验证云端对象与图片规格。

## 推荐架构

| 位置 | 职责 |
| --- | --- |
| D2 | 保留原图、原片和现有归档；另存生成的小封面备份 |
| BOH | 从已有云端媒体准备小封面，上传并验证；任务暂存按完成条件清理 |
| 独立图片对象存储 + CDN | 保存、分发网页缩略图；CDN 未命中时从图片存储取小图，不回源 D2 解析原文件 |
| 网站服务器 | 作品列表、鉴权与轻量封面索引，向页面提供准备好的缩略图地址 |

推荐独立图片存储，是因为网站主机当前磁盘 99% 已用、仅余 1.18 GB。22,296 张小图按每张 40 KB 估算就约 0.89 GB，尚未计旧版本和其他运行文件；不在该主机部署全量图片文件缓存。图片存储/CDN 需选定并配置可用服务，当前未开通或部署。

## 统一规格

每条作品只准备一张网页缩略图：最长边不超过 640 像素、保持比例、不放大，目标 20–60 KB。默认静态 WebP；已经满足尺寸、体积和解码要求的 JPEG 可直接复用。复杂图片的压缩质量需用真实样本验证，这些数字是设计目标。

上游已有 `cover.jpg` 也必须检查实际尺寸和编码，不能因文件名或引用存在而直接判定合格。来源依次按实际可用资产处理：已有封面、图文第一张图、视频修复产物或可解码视频帧。无可用源、权限受限或解码失败的条目明确记为失败，不生成假封面。

原图、原视频和旧归档对象保留；历史媒体处理在 BOH，不将历史视频下载到网站主机。图文任务只需处理用于封面的那张图，不读取整套相册；视频优先复用现有修复生成的封面，避免重复下载与转码。

## 生成与发布

1. 以用户 ID、作品 ID、源对象版本和处理版本建立任务；复跑只处理缺失、失败或来源已变化的封面。
2. 在 BOH 生成或复用小图，验证完整解码、尺寸、字节数和内容哈希。
3. 上传到独立图片存储并验证可读，预热实际使用的 CDN 地址；D2 备份遵守现有上传额度，单独记录完成状态。
4. 发布已验证的缩略图引用；生成、线上可用、D2 备份和失败分别统计，不能混算完成。
5. 上传、校验满足相应任务完成条件后清理暂存；失败项保留明确原因，按任务恢复，不无限堆积源媒体。

使用独立的轻量封面索引，键包含用户 ID 与作品 ID；对象地址带内容版本，不使用会变更的昵称。新版本验证后替换索引引用，旧版本仍可用于回退。

不让此任务直接覆盖当前视频队列依赖的 `cover_file`、`files` 和下载历史。现有发布程序检查 `previous_cover_file`，并发改写会被拒绝；参见[发布校验](../../../../../scripts/cloud_playback/publish.py:37)。网站读取封面索引，不按文件下标猜缩略图。涉及监控状态的写入仍通过 `MonitorStorage.update_state` 锁内合并。

缩略图沿用网站现有访问权限；CDN 地址鉴权、内容版本缓存键和到期行为需一同验证，不能因为启用缓存而把私有媒体变成公开文件。浏览器与 CDN 缓存用内容版本更新，避免每次翻页加随机参数导致重新下载。

## 页面加载

作品列表响应同时给出可用的小封面地址。优先加载可见卡片，只预取临近下一屏的少量图片；使用实际滚动容器判断可见范围，不仅依赖浏览器原生 `loading="lazy"`。翻页或切换用户时取消过期的等待请求。

保留图片固定占位尺寸，避免加载时页面跳动。图片域名使用 HTTPS 和 HTTP/2；服务端需要的网络请求复用连接。先迁移验证通过的作品，迁移中的其他作品保留现有展示，失败状态进入明确的任务记录。

## 全量推进

1. 新作品接入统一生成流程，避免继续产生大封面或缺少独立封面。
2. 用 iamsoyi 及视频、图文混合账号做试点，确认小图可读、鉴权、原图保留和首次加载性能。
3. 按用户轮转补齐所有用户最新一页，再处理其余历史作品；新作品优先，避免作品多的账号长期占用整个队列。
4. 复核 22,296 条快照任务，并持续处理快照之后的新增作品；来源删除或变化单独记录，不从旧快照恢复已删除记录。

BOH 从低并发开始，结合正在执行的视频任务调整；复用其已验证封面，共享上传额度监控，不另建一套全量视频下载或转码任务。

## 验收与依赖

验收覆盖全部有来源的图文与视频、旧记录、改名账号、翻页、新设备及失败条目。核对每个线上索引的对象存在、完整图片可解码、规格符合要求；原图/原片标识与内容不变。

使用实际访问域名，固定并记录网络、设备、视口和封面数量；分别测浏览器首次访问、CDN 未命中、再次访问和切换用户。建议目标：首张封面 95% 请求不超过 1 秒，首屏全部封面 95% 场景不超过 2 秒；这是待验证目标，当前未实现，不能保证任意公网条件都达到。

实施前仍需确定图片存储/CDN 的可用账号、域名、部署区域与费用预算，并验证其与现有网站鉴权兼容。方案预估小图净存储约 0.45–1.34 GB；版本、备份、请求及流量费用另计，当前没有账单估算依据。不因缺少这些信息开通收费服务。
