## 当前结果

20:19 CST 的最终核对覆盖 22,311 条记录：22,285 张封面有效，剩余 26 张，涉及 22 个用户，已发布图片校验失败为 0。该结果将全量 HTTP 验收和随后新增 41 张的 HTTP、完整解码证据与当前文件 SHA-256 逐一匹配；20:44 CST 再次核对，记录版本、索引和图片大小均未变化。

首批只修复没有封面引用的记录，漏检了 10,861 个旧引用的实际可用性。本机、D2、沃盘及原作恢复批次现均已结束。婷婷和跳跳糖首屏、艾米粒儿第 2 页均为 20 / 20 张加载成功。剩余 24 条图文未取得原作数据，2 条视频归档没有可用画面；备用账号的校准页也进入验证码，尚未启动旧账号批量重试。新下载保存封面的机制已部署，整个补全任务仍未完成。

页面遇到图片错误会替换图片元素，后台补图后已打开的错误卡片不会自动重试；关闭并重新打开作品弹层会取得新封面地址。此行为与旧引用漏检分别记录，不能把原先的 404 归因于浏览器缓存。逐条缺失原因见[当前缺失明细](../../../../runtime/cover-loading-20260914/remaining-covers.md)。

## 已授权范围

用户要求“帮我补全所有封面，以后新下载的作品都要封面”，并要求继续执行。
初始缺少展示封面的范围为 515 个用户、11,450 条记录；最终按重新读取的当前记录和封面索引核对。
已有图文首图和有效归档封面继续展示；本次不批量改写原片、播放文件或下载历史。

## 实施方式

BOH 从已归档媒体提取实际视频帧，生成并验证 JPEG。网站只接收小图片，图片与独立 SQLite 索引保存在 `data/covers/`。
索引绑定用户 ID、作品 ID 和下载记录版本，对象采用内容哈希；图片写入成功后才发布索引。
页面通过有鉴权的封面接口读取已发布小图，原来的 `cover_file` 和文件下标保持原有含义，避免干扰正在运行的 D2 视频修复。

新下载会在记录成功和成功通知之前，完成独立封面的实际解码和持久化。封面失败的作品仍须重试；历史回填失败页不能跳过。
下载器不能在云端校验前删除源媒体，清理由现有校验目标大小的搬运流程负责。

历史队列按用户轮转，优先每位用户的最新作品。任务可恢复，保留明确失败原因和已验证回执。
源对象变化、原片没有画面、解码失败等条目需要实际处理，不能生成假封面或从分母排除后宣称全部完成。
BOH 小图副本保留用于恢复；D2 既有修复/备份继续遵守其上传额度，不阻塞网页小图发布。

## 容量与旧方案

14 日实施调研实测网站可用约 3.57 GB；11,450 张缺失小图按 20–60 KB 估算约 229–687 MB。
20:19 CST 核对的已发布 JPEG 合计 589,505,318 B（约 590 MB）；20:44 CST 网站磁盘可用 4,002,107,392 B（约 4.00 GB）。
[原独立图片存储/CDN 提案](history/20260914-object-storage-proposal.md)完整保留为后续扩展参考；本次无需开通新云服务。

## 验收

- 全量核对每条应有封面的作品，确认索引匹配当前记录、文件存在、哈希与图片解码有效。
- 实际网站检查婷婷和其他用户的卡片、视频 poster、翻页以及鉴权。
- 新下载的图文和视频都必须在成功前持久化封面；失败不能发成功通知或跳过后续重试。
- 原有视频修复队列、原片及下载记录不因独立封面发布被覆盖。
- 已有失败、未验证项和后台未完成任务单独记录；只有实际满足要求才能标记完成。
