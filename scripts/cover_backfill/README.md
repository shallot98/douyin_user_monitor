# Historical cover backfill

Run on the independent compute host (BOH), with Python 3.10+, `ffmpeg`,
`ffprobe`, and `nice`. The package uses the repository's `cloud_playback`
helpers and `douyin_user_monitor.monitor.playback_media`; it needs no Pillow.
For a slim deployment with stdlib Python only, include `playback_media.py`
under `douyin_user_monitor/monitor/` but omit that package's `__init__.py`,
which eagerly loads the full application and its third-party dependencies.
A full repository checkout instead uses the application's existing virtual
environment. Run commands from the repository or slim bundle root.

```sh
python -m scripts.cover_backfill.worker \
  --manifest /private/cover-manifest.json \
  --credentials /private/d2-credentials.json \
  --workdir /private/cover-run \
  --workers 2 --page-size 20 --media-timeout 120
```

The credentials JSON has `host`, `client_id`, `client_secret`, and optional
`access_token`, matching `cloud_playback.d2_client.Credentials`. Credentials
and signed source URLs never enter result receipts or progress output.

The manifest is an object with a `jobs` array. Each job contains:

```json
{
  "user_id": "3fcc1167-89e2-45b5-b99e-3401e112f46c",
  "aweme_id": "9001",
  "sec_user_id": "stable-douyin-sec-user-id",
  "downloaded_at": "2026-09-14T12:30:00+08:00",
  "source_relative_path": "nickname/9001.mp4",
  "source_paths": ["/vps/抖音视频/nickname/9001.mp4"],
  "nickname": "optional display name"
}
```

`user_id` is the site's stable identifier, never derived from a nickname.
`downloaded_at` and `source_relative_path` preserve exact record values for
the site's eventual revision check. List every user's jobs newest first.
The worker preserves that order, processes one page per user, and rotates
users until exhausted. It keeps at most `--workers` jobs in flight.

Only explicit native D2 archive candidates are tried. The next candidate is
used only after the observed D2 missing-file response (HTTP 404, code 5).
Every missing or failed candidate is recorded. Other lookup errors fail the
job. Source metadata is checked before extraction, and identity, content
identity, size, path, and available update timestamp are checked again
before publication.

The worker reads the source HTTPS URL directly through FFmpeg and extracts
one frame. It probes and completely decodes the resulting JPEG only. It
does not download a source video file, transcode videos, upload to D2, or
change the existing video queue. Execution on `hdz` is rejected before any
source access. Each media subprocess has the configured timeout; each D2
request retains the existing 30-second request timeout.

Each successful image is atomically published to
`covers/{user_id}/{aweme_id}.jpg`, then a durable `ready` receipt is appended
to `results.jsonl`. Receipts include `schema_version: 1`, input fields,
`input_revision` (SHA-256 of canonical job JSON), attempts, `source`,
`source_verified_after`, `cover_path`, `sha256`, `bytes`, `width`, and
`height`. Failed receipts retain their stage and sanitized diagnostic.
`nickname: null` is equivalent to omitting the optional nickname.

On restart, a matching latest ready receipt skips work only after the local
JPEG decodes and matches the recorded dimensions, bytes, and hash. A partial
image without a receipt is regenerated. Invalid prior images are retried
with an explicit `resume_error` in the new receipt. Journal entries are
never removed. An incomplete journal line left by a crash prevents producer
startup with an explicit error; preserve and repair that journal before
resuming. A process lock prevents concurrent producers in one work directory.

`progress.json` is atomically refreshed as jobs finish and contains totals,
active/completed/remaining counts, generated bytes, receipt offset, and up
to 20 failure samples. Any failed job makes the worker exit with status 1.

```sh
python -m scripts.cover_backfill.export \
  --workdir /private/cover-run --output /private/batches/0001.tar \
  --after-offset 0 --max-covers 500
```

An export verifies ready images against their recorded hashes, then
atomically creates a new tar without overwriting an existing batch. The tar
contains `batch.json`, ready-only `receipts.jsonl`, failed-only
`failures.jsonl`, and JPEGs at their normal `covers/...` paths. Empty JSONL
members are included. It contains no source videos or credentials.
Producer outputs stay in place. Transfer and site ingestion are separate operations.

`batch.json` supplies `after_offset` and `next_offset` as byte cursors into
the producer journal. Advance the saved cursor only after successful site
ingestion. Failed receipts advance the cursor, are counted in
`failed_receipts`, and retain full per-item details in `failures.jsonl`. A
concurrent unfinished last line is left for the next batch. Zero-cover
batches are valid. A modified/corrupted ready image fails export explicitly.
Keep separate work directories for independent manifest revisions when
old ready receipts still need to be exported.
